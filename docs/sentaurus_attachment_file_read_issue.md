# Sentaurus VM Agent Attachment File Read Issue Report

## 1. Background

The user is running Sentaurus TCAD simulations through a VM-based agent. The goal is to extract final electrical metrics from two existing Id-Vg curve files:

- `idvg_low.plt`
- `idvg_high.plt`

These files were generated by previous Sentaurus Device runs and are required to extract:

- `SS_low`
- `SS_high`
- `Vth_low`
- `Vth_high`
- `DIBL`
- `Ion`

The Sentaurus physical simulation completed successfully, but the post-processing step failed because the previous Inspect extraction script did not work reliably.

The preferred fallback method is to directly parse the DF-ISE text `.plt` files and extract the numeric data from the `Data { ... }` block.

## 2. Confirmed Existing Simulation Artifacts

From the same browser session context, the previous Sentaurus run produced the following artifacts:

- `idvg_low.plt`
- `idvg_high.plt`

Example run directory:

```text
/home/TCAD2022/STDB/web-agent-runs/run_20260626T194901Z_utb28nm-schemea-full-rerun-with-final-ss_b17abe
```

The run status was marked as failed only because the final Inspect extraction step failed.

The following steps completed successfully:

- SDE structure and mesh generation
- SDevice low-drain Id-Vg sweep
- SDevice high-drain Id-Vg sweep

Therefore, the `.plt` files should contain valid Id-Vg data.

## 3. Attachment Upload Attempts

The user attempted to upload the files to the VM agent.

### 3.1 First upload attempt

The session showed:

```text
Attachments uploaded to this session: idvg_low.plt, idvg_high.plt.
```

Later, the context also showed:

```text
Attachments available to the VM agent: idvg_high.plt, idvg_low.plt.
```

However, the assistant could only see the attachment names. The actual file contents were not exposed in the conversation context.

The assistant could not access the expected DF-ISE data block:

```text
Data {
  ...
}
```

As a result, the assistant could not parse the Id-Vg data or compute SS/Vth/DIBL/Ion.

### 3.2 Second upload attempt after converting to `.txt`

The user converted the files to:

- `idvg_low.txt`
- `idvg_high.txt`

The session showed:

```text
Attachments available to the VM agent: idvg_low.txt, idvg_high.txt.
```

But the VM agent context indicated that these files were not found:

```text
idvg_low.txt: file not found
idvg_high.txt: file not found
```

This suggests that the attachment metadata was passed to the assistant, but the actual file payload was not mounted or made readable by the VM-side agent.

## 4. Actual Problem

The assistant can see attachment metadata such as file names, but cannot reliably access the actual file contents.

Observed behavior:

1. `.plt` files appear as uploaded or available.
2. The assistant sees only file names, not file bodies.
3. The expected `Data { ... }` block is not visible.
4. Converted `.txt` files appear in metadata but are reported as `file not found`.
5. The assistant cannot compute final metrics without the actual numerical data.

## 5. Expected Behavior

When the user uploads files, the VM agent should be able to access the actual file contents.

For example, if the user uploads:

```text
idvg_low.plt
idvg_high.plt
```

The backend should make them available to the agent through one of the following mechanisms:

- Inline file content in the agent context
- A mounted local file path accessible inside the VM
- A safe file-read API exposed to the VM agent
- A copied file under the current run/session workspace
- A downloadable artifact path that can be read by the agent

```text
Data {
  ...
}
```
